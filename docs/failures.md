# Failures - the product's own rows (D.9.3)

One row per fixed defect: the symptom, the cause, the measurement that confirmed it, the
version it was fixed in, and the regression test that now holds it. Every test here was
shown failing on the build that had the defect before it was trusted (rule 13).

| Symptom | Cause | Confirming measurement | Fixed in | Regression test |
|---|---|---|---|---|
| Bypass in Spectral mode did not null against the input; the residual sat at the signal level | The dry and bypass paths were delayed with a per-block shift instead of a delay line, so the first `latency` samples of *every* block were zeroed and the last `latency` samples dropped | `python3 "sound design/proto/measure.py" bypass` -> residual peak -12.0 dBFS (target < -120) | 0.1.0, prototype 1 | `measure.py bypass` (prototype) and `Health.test_bypass_nulls` (port) |
| `Source/Params.h` would not compile | The parameter id `auto` is a C++ keyword, and `paramgen.py juce` writes it as an identifier (`inline constexpr const char* auto = "auto";`) | `cmake --build --preset release` -> `error: expected unqualified-id` | 0.1.0 | `parameter_table` (`tools/tests/check_table.py`) plus the id rename to `autoLearn`; `paramgen.py check` itself does not catch keywords yet (a skills-bob item, see docs/status.md) |
| Frequency and Width jumped to nonsense on the first block after `reset()` | The log-domain smoothers (`smoothing_domain = log`) hold `log2(value)`, but `reset()` seeded them with the linear value, so the first update computed `2 ** 7000` | `python3 "sound design/proto/measure.py" latency` -> `RuntimeWarning: overflow encountered in scalar power` | 0.1.0, prototype 1 | the whole prototype suite runs under `-W error::RuntimeWarning`; `measure.py reset` holds the reset path |
| The harness aborted with `malloc(): corrupted top size` on a block larger than the one announced | The harness sized its work buffer to `--max-block` and then rendered blocks of `--block`, so `--block=1024 --max-block=256` wrote 1024 samples into a 256-sample allocation. The plugin was never at fault - the test that is *for* this case could not reach it | `ctest -R suite_fast` -> `RateAndBlock.test_block_larger_than_announced` aborted with signal 6 | 0.1.0 | `RateAndBlock.test_block_larger_than_announced` (it only started passing once the harness was fixed) |
| In Spectral mode the Spectral band shape was wider than Split's, so changing Mode changed how much a nearby /f/ was touched | The bins were weighted with the band-pass magnitude `\|BP\|`. Split's bell is minimum-phase and its phase narrows the skirts, so the right weight is the peaking-EQ magnitude at that gain | `measure.py selectivity` -> /f/ at 4 kHz: Split -0.44 dB, Spectral -0.94 dB (0.5 dB apart); after the fix -0.44 and -0.51 | 0.1.0, prototype 1 | `measure.py selectivity` holds both modes to the brief's 0.5 dB |
| The test phrase labelled 13 esses but held only 10 | `phrase()` wrote into a fixed 6 s buffer while its syllable grid ran to 7.5 s, and `_place` silently clipped. The ess-map test was asking for 13 events from audio that had 10 | `measure.py essmap` -> 12 events, 10 on a labelled ess | 0.1.0, prototype 1 | the buffer is sized from the grid and `_place` now raises; `measure.py essmap` asserts 13 of 13 |
| Sweeping Frequency fast put a sideband 1.5 kHz from the tone at -50 dB | Coefficients were recomputed once per 32 samples, and 48000/32 = 1500 Hz is exactly where the sideband sat | `measure.py zipper` -> -50.5 dB against the tone (target < -60); control block 8 -> -64.9, 1 -> -90.9 | 0.1.0, prototype 1 | `measure.py zipper` |
